Beyond the core form controls, Terminality ships a set of single-purpose widgets: a keyboard-driven value slider, a collapsible container, a self-invalidating drawing surface for custom visuals and animations, and an absolute-positioning container for non-linear layouts.

---

## Slider

`Slider` is a draggable value range control driven entirely by the keyboard. Left/Right (or Up/Down when vertical) move the handle by `Step`; the visual fills proportionally between `Minimum` and `Maximum`.

### Properties

<ParamField path="Minimum / Maximum" type="float" default="0.0f / 100.0f">
  The value range the slider covers.
</ParamField>

<ParamField path="Value" type="float" default="0.0f">
  The current value. Assign it to move the handle programmatically.
</ParamField>

<ParamField path="Step" type="float" default="1.0f">
  The amount each key press adds or subtracts.
</ParamField>

<ParamField path="Orientation" type="Orientation" default="Orientation::Horizontal">
  `Horizontal` uses Left/Right; `Vertical` uses Up/Down.
</ParamField>

### Events

<ParamField path="ValueChanged" type="Event<float>">
  Fired with the new value after every keyboard or programmatic change.
</ParamField>

### Example

```cpp
auto volume = init<Slider>([](Slider* s)
{
    s->Minimum = 0.0f;
    s->Maximum = 11.0f;
    s->Step    = 1.0f;
    s->Orientation = Orientation::Horizontal;

    s->ValueChanged += [](float value) { /* value in [0, 11] */ };
});
```

Use `Fraction()` to read the normalized handle position in `[0, 1]` — handy when rendering a custom slider of your own.

## Expander

`Expander` shows a header row with a toggle glyph and reveals its content only when expanded. The collapsed control measures to just the header row, so surrounding layout reflows automatically.

### Properties

<ParamField path="Header" type="std::wstring" default='L""'>
  The caption rendered on the header row.
</ParamField>

<ParamField path="Expanded" type="bool" default="false">
  Expansion state. Toggling triggers a full measure pass so the layout reflows.
</ParamField>

<ParamField path="Content" type="unique_ptr<ControlBase>" default="nullptr">
  The single child revealed when expanded. Like `Border::Content`, reassigning it detaches the old child cleanly.
</ParamField>

<ParamField path="CollapsedGlyph / ExpandedGlyph" type="wchar_t" default="'+' / '-'">
  The glyphs drawn on the header row for each state.
</ParamField>

### Events

<ParamField path="ExpandedChanged" type="Event<bool>">
  Fired with the new state after every toggle.
</ParamField>

### Example

```cpp
auto details = init<Expander>([](Expander* e)
{
    e->Header = L"Advanced options";

    e->Content = init<StackPanel>([](StackPanel* p)
    {
        p->AddChild(init<CheckBox>([](CheckBox* cb) { cb->Text = L"Verbose logging"; }));
        p->AddChild(init<CheckBox>([](CheckBox* cb) { cb->Text = L"Debug mode"; }));
    });

    e->ExpandedChanged += [](bool expanded) { /* persist the state */ };
});
```

Keyboard: Enter or Space toggles the expansion when the header is focused. `Expand()`, `Collapse()`, and `Toggle()` do it programmatically.

## Canvas

`Canvas` is a self-invalidating drawing surface for free-form rendering. Assign an `OnRender` callback and it is invoked **every frame** with the render context (scoped to the canvas area) and the delta time since the previous frame — the visual is effectively never validated, which makes it the building block for animations and custom-drawn widgets.

### Callback

```cpp
std::function<void(RenderContext& context, float dt)> OnRender;
```

### Example — animated sine graph

```cpp
auto canvas = init<Canvas>([](Canvas* c)
{
    c->HorizontalAlignment = HorizontalAlign::Stretch;
    c->VerticalAlignment   = VerticalAlign::Stretch;

    float phase = 0.0f;

    c->OnRender = [phase](RenderContext& context, float dt) mutable
    {
        phase += dt * 2.0f;

        const Rect area = context.ContextRect();
        const int midY  = area.Height / 2;

        for (int x = 0; x < area.Width; ++x)
        {
            const float y = midY + std::sin(phase + x * 0.25f) * (area.Height / 3.0f);
            context.SetCell(x, static_cast<int>(y), L'*', Color::CYAN, Color::BLACK);
        }
    };
});
```

<Warning>
Because `OnRender` runs every frame, keep the callback cheap — the whole UI frame budget is shared. For static custom visuals, subclass `ControlBase` and implement `RenderOverride` with normal dirty-rect invalidation instead.
</Warning>

## Heap

`Heap` is an absolute-positioning container: each child is pinned to an explicit point, and the heap measures to the bounding box of its children. It is the escape hatch for non-linear layouts — overlays, diagrams, floating tooltips — anywhere a `Grid` or `StackPanel` does not fit.

### Methods

<ParamField path="AddChild(Point position, child)" type="method">
  Pins `child` at `position` and returns a raw pointer to it. An `(x, y)` overload is available.
</ParamField>

<ParamField path="RemoveChild(child)" type="method">
  Detaches and returns the child by raw pointer.
</ParamField>

<ParamField path="Clear()" type="method">
  Removes all children.
</ParamField>

<ParamField path="Count()" type="method">
  Number of pinned children.
</ParamField>

### Example

```cpp
auto heap = init<Heap>([](Heap* h)
{
    h->HorizontalAlignment = HorizontalAlign::Stretch;
    h->VerticalAlignment   = VerticalAlign::Stretch;

    h->AddChild(Point(2, 1),  init<Label>([](Label* l) { l->Text = L"Origin"; }));
    h->AddChild(Point(20, 8), init<Label>([](Label* l) { l->Text = L"Over here"; }));
    h->AddChild(40, 3, init<Button>([](Button* b) { b->Text = L"Floating action"; }));
});
```

Focus navigation between pinned children follows insertion order, with arrow-key routing handled by the heap itself.
